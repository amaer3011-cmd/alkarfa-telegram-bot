# 🔥 الكارفة — بوت إعادة تسمية وتنسيق الملفات (مرات الكارف)

بوت تيليجرام احترافي مبني بلغة Python (Pyrogram v2) لإعادة تسمية الملفات،
وإرفاق صورة مصغرة دائمة، وتطبيق تسمية توضيحية مخصصة، مع وضع خاص لتنسيق
القنوات تلقائيًا — **كل ذلك عبر أزرار تفاعلية بدون أي أوامر نصية** (باستثناء
أمر `/start` الذي يتطلبه تيليجرام لبدء المحادثة).

## ✨ المزايا

- **🖼 صورة مصغرة دائمة** — من قائمة «الصورة المصغرة»: تعيين، عرض، أو حذف.
  يتم تصغير الصورة تلقائيًا إلى 320×320 مع الحفاظ على النسب، وتحويلها إلى JPEG.
  كما يمكنك إرسال صورة مباشرة في أي وقت وسيسألك البوت إن كنت تريد استخدامها.
- **📁 إعادة تسمية الملفات** — أرسل أي مستند أو فيديو أو ملف صوتي، واختر
  «✏️ إعادة تسمية» أو «📁 الاحتفاظ بالاسم الحالي». شريط تقدم حي يعرض
  النسبة المئوية، الحجم المنقول، السرعة، والوقت المتبقي أثناء التحميل والرفع.
- **✏️ تسمية توضيحية ديناميكية** — من قائمة «التسمية التوضيحية»، مع دعم
  المتغيرات: `{filename}`، `{filesize}`، `{duration}`.
- **📢 وضع تنسيق القنوات (للمشرفين)** — ربط البوت بقناة كمشرف، ليقوم تلقائيًا
  باعتراض كل مستند يُنشر فيها، وإعادة تنسيقه بالصورة المصغرة والتسمية
  التوضيحية الموحّدة للقناة، ثم استبدال المنشور الأصلي.
- **⚙️ متين وموثوق** — معالجة كاملة لأخطاء `FloodWait`، وتنظيف الملفات
  المؤقتة تلقائيًا حتى عند حدوث خطأ، مع تحكم في معدل تحديث شريط التقدم
  لتفادي حدود تيليجرام.

- **📄 صورة أول صفحة في الـ PDF (جديد)** — من «📄 صورة أول صفحة في الـ PDF»
  احفظ صورة ليضعها البوت تلقائيًا في أول صفحة من أي PDF ترسله، بوضعين:
  *إضافة كصفحة جديدة قبل الأولى* أو *استبدال الصفحة الأولى*. وعند إرسال PDF
  تظهر أزرار لاختيار صورة **لهذا الملف فقط**، تغيير الوضع، تخطي الصورة، أو
  استخدام صورتك المحفوظة. القنوات لها صورة خاصة بها أيضًا.
- **⚡ تحسينات** — أكثر من ملف في نفس الوقت (كل ملف بأزراره)، حد للمعالجة
  المتزامنة، إعادة محاولة تلقائية عند FloodWait في التحميل والرفع (وفي القنوات)،
  صورة مصغرة تلقائية من أول صفحة للـ PDF إن لم تضبط صورة مصغرة،
  وخيار `ADMIN_IDS` لحصر إدارة القنوات.

## 🚀 التثبيت والتشغيل

1. أنشئ بوتًا عبر [@BotFather](https://t.me/BotFather) واحصل على التوكن.
2. احصل على `api_id` و `api_hash` من <https://my.telegram.org>.
3. انسخ الملف `.env.example` إلى `.env` واملأ القيم المطلوبة:
   - `API_ID`, `API_HASH`, `BOT_TOKEN` فقط
   - باقي الإعدادات داخلية ولها قيم افتراضية، ولا تحتاج إضافتها إلى `.env`
4. ثبّت المتطلبات:
   ```bash
   pip install -r requirements.txt
   ```
5. شغّل البوت:
   ```bash
   python main.py
   ```

## 🧭 كيفية الاستخدام

- أرسل `/start` لفتح **القائمة الرئيسية**.
- كل الإعدادات (الصورة المصغرة، التسمية التوضيحية، إدارة القنوات) تتم عبر
  الأزرار المعروضة — لا حاجة لحفظ أي أوامر.
- أرسل أي ملف في أي وقت وسيظهر لك البوت خيارات إعادة التسمية فورًا.

## 🧩 كيف تعمل الأزرار داخليًا

بما أن كل شيء أصبح تفاعليًا، يعتمد البوت على "حالة" واحدة لكل مستخدم
(`utils/state.py`) لمعرفة ما الذي ينتظره من رسالته التالية (اسم ملف جديد،
صورة، معرّف قناة، نص تسمية توضيحية...). كل الرسائل النصية والصور المرسلة
في الخاص تمر عبر موجّه مركزي واحد (`handlers/common.py`) يوزعها حسب هذه
الحالة على الوحدة المناسبة، بدلًا من أن تتنافس عدة معالجات على نفس الرسالة.

## 📢 إعداد وضع تنسيق القناة

1. أضف البوت إلى قناتك **كمشرف** مع صلاحيات «نشر الرسائل» و«حذف الرسائل».
2. من القائمة الرئيسية اختر «📢 إدارة القناة»
   ثم «🔗 ربط قناة»، وأرسل معرّف القناة الرقمي أو أعد توجيه أي منشور منها.
3. اختياريًا، اضبط صورة/تسمية خاصة بالقناة عبر «🖼 تعيين صورة القناة» و
   «✏️ تعيين تسمية القناة».
4. من الآن، كل مستند يُنشر في القناة سيُحمَّل ويُعاد تنسيقه ونشره تلقائيًا،
   مع حذف المنشور الأصلي.

## 📌 ملاحظات حول التوسّع

- حالة "الانتظار" لكل مستخدم محفوظة في الذاكرة (dict) — مناسبة لعملية واحدة
  (single process). عند التشغيل على عدة عمليات/خوادم، استبدلها بـ Redis
  حتى لا تُفقد الحالة عند وصول رسائل المستخدم إلى خادم مختلف.
- اتصالات `aiosqlite` تُفتح لكل عملية على حدة بدل الاحتفاظ باتصال عام؛
  لأداء أعلى تحت ضغط كبير، ننصح بالتحويل إلى PostgreSQL أو استخدام تجميع
  اتصالات (connection pool).

## 🌐 النشر (Deployment)

**تشغيل مباشر على سيرفر:**
```bash
cp env.example .env      # املأ API_ID و API_HASH و BOT_TOKEN
pip install -r requirements.txt
python main.py
```
للتشغيل الدائم استخدم `systemd` أو `pm2` أو `screen`.

**بـ Docker:**
```bash
docker build -t media-bot .
docker run -d --name media-bot --restart unless-stopped \
  --env-file .env \
  -v $(pwd)/bot_database.db:/app/bot_database.db \
  -v $(pwd)/thumbnails:/app/thumbnails \
  -v $(pwd)/covers:/app/covers \
  -v $(pwd)/file_renamer_bot.session:/app/file_renamer_bot.session \
  media-bot
```
> ⚠️ ملفات `.env` و `*.session` و `bot_database.db` فيها بيانات حساسة — لا ترفعها على GitHub (موجودة في `.gitignore`).

**إعدادات الأداء** (في `config.py`): `MAX_CONCURRENT_JOBS` عدد الملفات المعالجة معًا،
`MAX_CONCURRENT_TRANSMISSIONS` عدد النقل المتزامن، `UPDATE_WORKERS` عمّال معالجة الأزرار.
قلّلها على السيرفرات الضعيفة. حدّ حجم الملف 2 جيجا (`MAX_FILE_SIZE`).

**الترقية من نسخة قديمة:** استبدل ملفات الكود فقط، واترك `bot_database.db` و`*.session`
و`thumbnails/` كما هي — قاعدة البيانات تتحدّث تلقائيًا عند أول تشغيل.


## 👑 لوحة الأدمن (جديد في الكارفة)

اضبطي `OWNER_IDS` في `.env` (ID حسابك، من @userinfobot)، وبعدها ابعتي `/admin`
أو اضغطي «👑 لوحة الأدمن» في القائمة الرئيسية. اللوحة ليكي إنتي بس.

- 📊 إحصائيات (المستخدمين، الجداد، النشطين، المحظورين، الملفات، القنوات)
- 👥 قائمة المستخدمين (صفحات) + كارت لكل مستخدم: حظر / فك حظر / ابعتله رسالة
- 🔍 بحث بالـ ID أو @username
- 🚫 / ✅ حظر وفك حظر بالـ ID
- 📣 إذاعة (نص أو صورة) لكل المستخدمين غير المحظورين، مع تقرير في الآخر
- 🛠 وضع الصيانة (البوت يقفل على الكل ما عدا الأدمن)
- 💬 تغيير رسالة `/start` أو الرجوع للأصلية
- 📢 إدارة القنوات
- 📄 تصدير المستخدمين CSV

> المستخدمين القدام بيظهروا في القائمة من أول ما يتفاعلوا مع البوت بعد التحديث
> (الاسم و@username بيتسجلوا وقتها). قاعدة البيانات بتتحدّث تلقائيًا.
> لو عايزة إدارة القنوات ليكي بس، حطي نفس الـ ID في `ADMIN_IDS` كمان.


## 🎬 الفيديو: علامة مائية وعنوان (جديد)

من القائمة الرئيسية «🎬 إعدادات الفيديو»:

- 💧 **علامة مائية** نص (عربي أو إنجليزي، لحد 3 سطور) أو **لوجو** صورة، مع اختيار
  المكان (5 أماكن) والحجم (صغير/وسط/كبير) والشفافية (100/70/40%) ومعاينة قبل الاستخدام.
  الإيموجي مش بتظهر على الفيديو وبتتشال من النص.
- 🏷 **عنوان افتراضي** (يدعم `{filename}`)، و📺 خيار يعرض العنوان على الشاشة أول 5 ثواني.
- عند إرسال أي فيديو بتظهر أزرار: تفعيل/إلغاء العلامة **لهذا الفيديو فقط**، وكتابة
  **عنوان لهذا الفيديو** أو «بدون عنوان».

**ازاي بيشتغل:**
- العنوان بيتكتب دايمًا في بيانات الفيديو (metadata). لو اتحط في البيانات بس، الفيديو
  بيتنسخ **من غير إعادة ترميز** (سريع ومن غير خسارة جودة). تيليجرام نفسه بيعرض اسم
  الملف مش عنوان البيانات، لكن مشغلات تانية (VLC وغيره) بتعرضه.
- العلامة المائية أو العنوان على الشاشة بيحتاجوا **إعادة ترميز** الفيديو لـ H.264 / mp4
  (ممكن تاخد وقت وتستهلك CPU حسب طول الفيديو وقوة السيرفر). الصيغ التانية (mkv مثلًا)
  بتتحوّل لـ mp4 في الحالة دي.
- لو ffmpeg مش متثبّت أو حصل خطأ في التعديل، الفيديو بيتبعت زي ما هو مع تنبيه.
- **المتطلبات:** `ffmpeg` على السيرفر (الـ Dockerfile بيثبّته مع خط DejaVu). للتشغيل
  المباشر: `sudo apt install ffmpeg fonts-dejavu-core`.
- **الأداء:** `MAX_CONCURRENT_ENCODES` (الافتراضي 1) و`VIDEO_PRESET` و`VIDEO_CRF` في `.env`.
- وضع القنوات التلقائي لسه للمستندات فقط، ومش بيطبّق علامة الفيديو.


## ✅ ضمان سلامة الملفات والفيديو (جديد)

أي ملف أو فيديو بيخرج من البوت بيعدّي على فحوصات (`utils/integrity.py` و`verify_video` في `utils/video_edit.py`):

- **التحميل:** الحجم لازم يساوي حجم الملف على تيليجرام، وإلا بيتلغي ويطلب إعادة الإرسال.
- **الفيديو:** بعد أي تعديل بيتفحص (فيه صورة وصوت، المدة مطابقة، بداية ونهاية الفيديو بتتفك من غير أخطاء). لو فشل الفحص بيتبعت **الأصلي** مع تنبيه.
- **الصوت:** AAC بس هو اللي بيتنسخ زي ما هو؛ أي صوت تاني (ac3/dts/opus...) بيتحوّل AAC عشان يشتغل في تيليجرام.
- **الـ PDF:** بيتاخد نسخة احتياطية، وبعد التعديل بيتفتح ويتفحص (عدد الصفحات + عرض الصفحات)، ولو فيه مشكلة بيرجع الأصلي. إزالة العلامة بتشيل النص المطابق بس (من غير ما تمسح صور أو خطوط أو خلفيات، ومن غير مربعات بيضاء).
- **الرفع:** بعد الإرسال بيتأكد إن الحجم على تيليجرام = الملف المرسل، ولو مختلف بيعيد الرفع مرة. في القنوات المنشور الأصلي **مش بيتحذف** إلا بعد ما النسخة الجديدة تتأكد.
- **الأسماء:** الاسم الطويل (عربي) مش بيقطع الامتداد، والاسم اللي فيه نقطة زي `محاضرة 1.5` بياخد الامتداد الأصلي، والملف المحلي المؤقت باسم قصير فمفيش خطأ "File name too long".
- الكابشن بيتقص عند 1024 حرف (حد تيليجرام)، والقالب الغلط مش بيوقف الرفع. الفيديو بيتبعت بأبعاده ومدته الحقيقية وصورة مصغرة تلقائية.


## 🚂 النشر على Railway

1. ارفع المشروع على GitHub (الـ `.gitignore` بيمنع رفع `.env` والجلسة وقاعدة البيانات) وأنشئ Project على Railway من الريبو. هيستخدم `Dockerfile` تلقائيًا (فيه ffmpeg والخطوط).
2. **Volume (مهم):** من Service → Settings → Volumes أضف Volume واعمل Mount Path = `/data`. من غيره قاعدة البيانات وجلسة تيليجرام والصور المصغرة بتضيع مع كل نشر.
3. **Variables:** `API_ID` و`API_HASH` و`BOT_TOKEN` و`OWNER_IDS` (ومعاهم `DATA_DIR=/data` لو Railway ما ضبطش `RAILWAY_VOLUME_MOUNT_PATH` تلقائيًا). اختياري: `ADMIN_IDS`, `TIMEZONE`, `MAX_CONCURRENT_ENCODES`.
4. البوت Worker (مفيش Port ولا Domain). شغّل **نسخة واحدة فقط** (Replicas = 1)، لأن تشغيل نسختين بنفس التوكن بيعمل تعارض.
5. تشفير الفيديو بياخد CPU: لو السيرفر ضعيف خلّي `MAX_CONCURRENT_ENCODES=1` وفكّر في `VIDEO_PRESET=ultrafast`.
